Шаг 6 плана переезда (вариант 2, «да» Сергея 15.10.2026). Это всё, что нужно знать, чтобы сделать или
поправить день музея. Что и как писать (хук, источник, механика, вау-эффект) — по-прежнему в скиллах
музеев, их содержание не менялось. Меняется только то, **как страница собирается**.

## 1. Как устроено

- День музея — **одна карточка**: `src/content/days/<музей>/<ММ-ДД>.json`. Страница дня, календарь и
  витрина музея собираются из карточек сами; руками их не верстают.
- **Все дни большие (Сергей, 20.10.2026, Р58).** «Карточка» — это файл данных дня, не короткая страница:
  у каждого дня — полная страница; короткие карточки (3–5 доп. событий) — только внутри дня. Пометки «(большой)» не ставить.
- Музеи — `src/data/museums.json`. Имя музея — только `title_ru` оттуда, дословно и полностью.
- Шаблоны — `src/pages/` (главная, музей, календарь, день, карта). Вид — только `public/assets/*.css`.
- Интерактивы и движки — `public/assets/*.js`, те же, что на старом сайте, без переделки.
- Превью: https://arabelthera-dot.github.io/rc-site/ · карта стандарта: https://arabelthera-dot.github.io/rc-site/karta/

## 2. Где правда

- **С 17.10.2026 18:46 МСК (переключение адреса)** правда — карточки здесь, в `rc-site`. По старому адресу
  `rc-museum-preview` теперь отдаётся этот сайт; старый репозиторий — архив, только чтение, новое туда не пишется.
- Календарь (запись дня) — **один путь**: таблица `data/tablicy/<музей>/` → `node scripts/tablicy/razbor.mjs --zapis` →
  `src/content/days/<музей>/ММ-ДД.json` → сборка. Старый перенос календарей из `calendar-*.js` (`import-legacy.mjs`)
  и генераторы AI_Projects — в архиве (`archive/kalendar-staryy-put-2110/README.md`, 21.10.2026), не возвращать.
- `npm run import` (переадресации и полные страницы со старого сайта) заперт и без флага `IMPORT_POSLE_PEREKLYUCHENIYA=1`
  не запускается — ручные правки карточек он больше не затирает. Флаг — только по заданию оркестратора.
- Картинки, ролики и звук дня — в `public/muzei/<музей>/…`; если в карточке или полной странице ссылка на файл,
  которого там нет, проверка заявки красная.

| Поле | Что это | Правило (проверяет сборка) |

| `museum`, `key` | slug музея, дата `ММ-ДД` | ключ строго `ММ-ДД` |

## 5. Как сдать работу

1. Ветка `<твоя подпись>/<тема>` от свежего `main`, коммит обычным `git commit` своей подписью.
2. Проверить у себя: `npm ci && npm run build` — без ошибок.
3. Заявка: `gh pr create`, сразу `gh pr merge <N> --auto --squash`.
4. Проверка `sborka-i-ssylki` (сборка + битые внутренние ссылки, порог 0) зелёная — заявка сливается
   сама, сайт выкладывается сам. Красная — чини в той же ветке. В `main` напрямую не пишется.
5. Сдача = слитая заявка. Результат — ссылкой на живую страницу, проверенной на открытие.
