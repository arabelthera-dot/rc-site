# Каналы — ежедневный пост в Telegram и VK

Вариант А (Сергей 18.10.2026). Каждый день в 9:00 МСК (`cron 0 6 * * *` UTC) GitHub Actions
(`.github/workflows/kanaly.yml`) запускает `scripts/kanaly/post.py` и ставит пост дня в Telegram-канал и
сообщество VK «Русская цивилизация». Бесплатно: только Actions и API площадок.

**Что в посте.** День — сегодняшняя дата по Москве. Берутся музеи, у которых на этот день есть карточка с хуком
и большая страница (`src/data/full-pages/<музей>/<ММ-ДД>.html`). Главный — по кругу (порядок по номеру в
каталоге): картинка дня, «дата · title_ru», хук дословно, ссылка на живую страницу дня. Остальные (до трёх) —
строкой «Сегодня также». Адрес собирается из `site`/`base` в `astro.config.mjs` — смена домена подхватится сама.
Картинка — первая из `images` дня, а если её нет — первая картинка большой страницы; карточки-превью с надписью
не берутся (текста на картинке нет), такой день идёт только в «Сегодня также». Нет ни одного подходящего музея —
поста в этот день нет, работа зелёная.

**Проверка перед отправкой (Е8, Р47, 20.10.2026).** Пост проходит `scripts/kanaly/proverka.mjs` — те же функции,
что у сборки, общим модулем `src/lib/proverka-posta.mjs`, без копии правил:

| Что | Чем проверяется |
|---|---|
| хук одним предложением, до 200 знаков, источник, подписи кадров | схема дня `src/content.config.ts` (грузится через Vite, как в Astro) |
| имя музея — `title_ru` полностью | `checkMuseumName` из `src/lib/imya-muzeya.mjs` (её же зовёт сборка полных страниц) |
| имена из реестров Минюста | `sverkaTekstov` из `src/lib/zakon.mjs`, исключения — `data/reestry/isklyucheniya.json` |
| возраст: 16+ не идёт (тихий трагический день), на 12+ знак в посте | `src/lib/vozrast.mjs`, `src/data/vozrast.json` |
| картинка — файл сайта, кадр дня с подписью, XX век — с основанием прав | `kadrXX` из `src/lib/zakon.mjs`, `data/reestry/osnovaniya.json` |
| ссылки — только на `site` из `astro.config.mjs` и открываются с ответом 200 | GET с тремя попытками |

Брак — пост не уходит ни на одну площадку, каждая причина строкой `::error::` в журнале и в сводке работы, работа
красная. День-замена не подставляется: пропущенный музей (16+, нет картинки для главного) — строкой «Пропуск…».
Пока секретов нет (каналы — М33), проверка идёт в журнал, а работа зелёная. Пробы — `node scripts/kanaly/proverka.test.mjs`
(шаг `kanaly — пробы проверки поста` в `proverka.yml`): заведомый брак отклонён, нормальный пост проходит, без сети.

**Как включить.** Settings → Secrets and variables → Actions → New repository secret:

| Секрет | Что |
|---|---|
| `TG_BOT_TOKEN` | токен бота от @BotFather; бот — администратор канала с правом публикации |
| `TG_CHANNEL` | `@имя_канала` или числовой id `-100…` |
| `VK_TOKEN` | токен с правами `wall`, `photos` (пользователь-администратор сообщества; токен сообщества `photos.getWallUploadServer` не умеет) |
| `VK_GROUP_ID` | id сообщества, число без минуса |

Нет пары секретов — площадка пропускается строкой «пропуск — нет секрета» в журнале, остальное работает.
Перед включением: Actions → kanaly → Run workflow с `dry_run` (галочка по умолчанию) — пост печатается в журнал,
ничего не уходит. Если работает старый `tg-bot/` с постом в канал — поставить ему `RC_TG_POST_CHANNEL=0`,
иначе в канале будет два поста в день.

**Повтор.** Отметка «уже отправлено» хранится в кэше Actions на дату и площадку; у VK вдобавок смотрится стена.
Повторный запуск в тот же день второй пост не ставит. Упала одна площадка — вторая всё равно идёт, работа красная;
перезапуск отправит только недошедшее.

**Комментарии VK (20.10.2026).** Модерации нет — пост уходит с `close_comments=1`; правила комментариев
сайта — `/pravila-kommentariev/`. Открыть комментарии у новых постов — переменная `VK_KOMMENTARII=1` в шаге
workflow. Уже опубликованные посты закрывает разовый `scripts/kanaly/vk_zakryt_kommentarii.py`: без флагов —
проба (печатает, что закрыл бы), действие (`wall.closeComments`) — только с `--primenit`.

**Как откатить.** Actions → kanaly → «…» → Disable workflow. Или удалить секреты — площадка выключится.
Уже вышедшие посты удаляются руками в канале/сообществе.

Пробно у себя: `python scripts/kanaly/post.py --dry-run [--date ММ-ДД] [--bez-seti]` (`--bez-seti` — ссылки не открываются).

## Почта «Сегодня в Русской цивилизации» (Р32, 20.10.2026; сервис и секрет — Михаил, М48)

То же утреннее сообщение, письмом подписчикам. Сервис — Unisender (российский). Каждый день в 9:00 МСК
`.github/workflows/pochta.yml` запускает `scripts/kanaly/pochta.py`: текст дня и проверка (Е8) — те же функции
`build()`/`check()` из `post.py`, без копии правил. Брак — письмо не уходит, работа красная. Отметка «уже отправлено» —
кэш Actions на дату, повторный запуск второго письма не шлёт. Подписка — форма под кнопкой Telegram
(`pochtaHtml` в `src/lib/sitebar.mjs`): адрес, обязательная галочка согласия на обработку ПД со ссылкой на
`/politika-konfidencialnosti/`; форма шлёт адрес прямо в сервис, ключ API в браузер не попадает, подписка —
с письмом-подтверждением (двойная, стандарт сервиса).

**Выключено по умолчанию.** Нет секрета `MAIL_API_KEY` — работа пишет «спит: нет MAIL_API_KEY (М48)» и выходит 0;
нет `PUBLIC_POCHTA=1` — формы на сайте нет, сборка та же, что раньше.

**Как включить.** Settings → Secrets and variables → Actions:

| Что | Где | Значение |
|---|---|---|
| `MAIL_API_KEY` | секрет | ключ API Unisender (кабинет → Настройки → Интеграция и API) |
| `MAIL_LIST_ID` | переменная | id списка подписчиков |
| `MAIL_SENDER_EMAIL` | переменная | подтверждённый в сервисе адрес отправителя на домене сайта |
| `MAIL_SENDER_NAME` | переменная | имя отправителя (пусто — «Русская цивилизация») |
| `PUBLIC_POCHTA_FORMA` | переменная | `action` из кода формы подписки (кабинет → Формы подписки, двойное подтверждение включено) |
| `PUBLIC_POCHTA_SPISOK` | переменная | id того же списка (поле `default_list_id` формы) |
| `PUBLIC_POCHTA` | переменная | `1` — форма видна на сайте; ставить последней, после пробы |

Перед включением: Actions → pochta → Run workflow с `dry_run` — письмо печатается в журнал, ничего не уходит.
Скрытые поля формы сверить с кодом формы из кабинета. Хост формы — внешний для шага `vneshnie-hosty`
(`proverka.yml`): если он отклонит адрес отправки формы, добавить хост сервиса в его список (сервис российский, Р38).
Пробно у себя: `python scripts/kanaly/pochta.py --dry-run [--date ММ-ДД] [--bez-seti]`.

**Как откатить.** Убрать переменную `PUBLIC_POCHTA` (форма пропадёт со следующей выкладкой) и Actions → pochta →
Disable workflow или удалить секрет `MAIL_API_KEY`. Весь код — revert заявки «почта». Подписчики остаются в списке
сервиса; удалить их — в кабинете Unisender.
