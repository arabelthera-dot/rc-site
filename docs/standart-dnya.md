# Стандарт дня (Р660, Сергей, 08.11.2026)

Единственный источник для помощников. Каждый день карточки страницы `src/content/dni-shablon/<музей>/ММ-ДД.yaml`
с ключом 02-01 и дальше, любой музей, не собирается, если нет хотя бы одного пункта ниже. Январь (ключ до 02-01)
этой проверкой не затронут.

Проверка: `src/lib/standart-dnya.mjs`, её вызывает загрузчик `zagruzitKartochki` в `src/lib/den-obshchee.mjs`.
Поля и их типы общие с записью дня `src/content/days`: `src/lib/forma-dnya.mjs` (форма Р635, смысл полей —
`src/data/forma-dnya.json`, там `punkt` = номер пункта отсюда). `npm run build` выдаёт все пробелы сразу, по одной
строке: `02-01 izobreteniya: нет пункта 17 — velichina_chislo`.

Картинки дня — это `oblozhka`, каждый кадр `figures`, `kadr` у ударов `story` и у ударов блоков `fakty`.
Факт — удар блока `fakty`.

Статус карточки (Р676): `status: zagotovka` — день в работе, пункты 171–173 не обязательны, на адрес `den` не идёт;
нет поля или `gotov` — весь состав. У записи дня `src/content/days` при `status: gotov` тот же состав: `fakty` — 10 основных
и 5 с `eshche: true`, у каждого `poluhuk`; у изобретений `igra`, у «Русских не сдаются» `vizual {tip, dannye}`;
`audio` и `video` — только при `pokazan_sergeyu` (проверка — `formaDnya` в `src/content.config.ts`).

Пункты 25 и 26 — поля картинки по желанию, сборку не останавливают (новых проверок нет, Р627):
`alt` у записи дня `src/content/days` — что видно на картинке для незрячих, не копия подписи (WCAG 1.1.1); нет поля —
alt берётся из `caption`, как раньше (у карточки страницы `alt` свой и был). `opisanie_dlinnoe` у любой картинки —
длинное описание схемы, карты, чертежа (WAI, сложные картинки): под картинкой раскрывается «Подробное описание
картинки», картинка ссылается на него `aria-describedby`.

## Чего машина не проверит

- 2: что победитель — подлежащее хука (это грамматика).
- 1 и 13: что номера не меняются со временем (машина видит только сегодняшнюю карточку).
- 18: что ответ правда единственный.
- 27: саму проверку символики (машина видит только флажок человека).
- 30: что на сущность одна карточка словаря.
- 20: правдивость паспорта прав.

## Проверка до сдачи (п. 49, Р631)

Это форма, а не сторож: схемы те же, что уже работают в `npm run build`, в сборку ничего не добавлено (Р627).
Помощник запускает две команды из своей копии сайта до коммита. Каждая идёт пару секунд, сайт не собирается.

1. Запись дня `src/content/days/<музей>/ММ-ДД.json` и копии утверждённых `src/data/utverzhdeno` — встроенная
   проверка Astro по схемам `src/content.config.ts` (zod):

   ```
   npx astro sync
   ```

   Код выхода 0 — форма цела. Брак — `InvalidContentEntryDataError` с путём к файлу и полем, код выхода 1.
   Astro читает настройки, а им нужны стили панели из `public/assets/`; в лёгкой копии без public/ один раз:
   `git sparse-checkout add /public/assets/` (5 МБ, 218 файлов).

2. Карточка страницы `src/content/dni-shablon/<музей>/ММ-ДД.yaml` — та же схема zod и стандарт дня (таблица выше),
   что в сборке:

   ```
   node -e "import('./src/lib/dni-shablon.mjs').then((m) => console.log('карточек', m.kartochki().length))"
   ```

   Чисто — строка `карточек N`. Брак — список `файл: поле: что не так` и `ДД-ММ музей: нет пункта N — поле`.
   Если в копии нет папки музея в public/, будут ещё строки «нет файла аудиогида», «игры … нет», «нет public/… .glb»:
   это не брак формы, а нехватка файлов в копии. Для полной сверки — `git sparse-checkout add /public/muzei/<музей>/`.

Строки `::warning::` (долг ссылок, долг кадров) — подсказки, не брак. Полная сборка идёт в заявке на GitHub.
