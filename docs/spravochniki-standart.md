# Справочники стандарта дня: источник и подлинник картинки (пункты 15 и 28)

Памятка помощнику, который собирает новый день февраля. Готовые дни не переделываем.

## Пункт 15. Источник — это запись, а не строка текста

Каждый источник дня записываешь отдельно, с полями:

- `n` — номер источника в дне (1, 2, 3…); на него ссылается факт полем `fakty.istochnik`;
- `baza` — короткое имя базы, только из списка `src/data/spravochniki/bazy.json` (раздел `razresheny`);
- `nazvanie` — что это: книга, карточка предмета, документ;
- `ssylka` — точный адрес той страницы, где ты это нашёл;
- по возможности: `avtor`, `god`, `nomer_v_baze` (номер в Госкаталоге, шифр дела), `stranica`, `provereno` (дата).

Пример:

    {"n": 1, "baza": "goskatalog", "nazvanie": "Старорязанский клад, опись 1893",
     "ssylka": "https://goskatalog.ru/portal/#/collections?id=16999502", "nomer_v_baze": "16999502"}

Список баз закрытый. В нём 112 баз: 111 российских из общего реестра
`~/projects/russian-civilization/docs/registries/sources.json` и белорусский музей warmuseum.by (Р469: белорусские музеи —
союзники, брать можно всё). Википедии, Викисклада, Викитеки, Wikidata в списке нет и не будет (Р90).
Иноагентов и запрещённых организаций нет нигде; их ловит `src/lib/zakon.mjs`.

Нужной базы нет в списке — не пиши её своим словом. Добавь её в общий реестр `sources.json` (с адресом и датой проверки) и
пересобери список: `python3 tools/spravochniki.py bazy`. Руками `bazy.json` не правят.

Проверить свои источники: положи их в файл и запусти `python3 tools/spravochniki.py istochnik файл.json` —
скрипт скажет, какого поля не хватает и какая база не из списка.

## Пункт 28. Подлинник картинки

На сайте лежит копия, уменьшенная и сжатая. Подлинник — файл в том качестве, в каком его отдаёт источник.
На каждую картинку дня — одна запись в `src/data/spravochniki/podlinniki.json`:

- `kopiya` — путь к копии на сайте (`muzei/<музей>/img/…`), `kopiya_sha256`, `kopiya_bayt`, `kopiya_px` — отпечаток копии;
- `baza` и `otkuda_skachan` — из какой базы и с какой страницы взят файл (точная карточка, не общая страница фонда);
- `podlinnik_gde` — где лежит подлинник: `u_istochnika` (лежит в базе по адресу `otkuda_skachan`) или `u_nas` (скачан);
- `podlinnik_fayl`, `podlinnik_sha256` — путь и отпечаток подлинника, если он скачан.

Правило хранения:

1. Диск тесный, поэтому подлинники крупным объёмом не качаем. По умолчанию подлинник остаётся у источника:
   `podlinnik_gde: "u_istochnika"` и точный адрес. Этого хватит, чтобы скачать его снова.
2. Скачиваем подлинник только тогда, когда источник может пропасть (сайт с пометкой dead или ru_only в реестре) или нужен
   крупный кадр. Кладём его вне git, в отдельное хранилище медиа (Р266), и записываем путь и sha256.
3. Копию для сайта делает машина из подлинника. Руками копию не правят и поверх подлинника не сохраняют.

Запись делает машина, руками её не пишут:

    python3 tools/spravochniki.py podlinnik <музей> <ММ-ДД> <номера картинок>

Скрипт берёт базу и адрес из подписи `credit` (`[goskatalog], https://…`), считает отпечаток копии и пишет ошибки:
«база не из списка», «нет адреса, откуда скачан».

Проба (08.11.2026, 3 картинки утверждённого января): «Не сдаются» 01-01 картинка 1, «Изобретения» 01-01 картинки 1 и 2.
Все три из Госкаталога, адрес найден, база есть в списке, ошибок 0. Подлинники не скачивали, они лежат у источника.

## 30. Одна карточка на человека, предмет, событие

Файл: `src/data/spravochniki/kartochki.json`. Машина: `python3 tools/spravochniki/kartochki.py`.

- У каждого человека, предмета, события — одна карточка с постоянным номером `tip:slug`
  (как в словаре `src/data/slovar.json`): `lyudi:german-titov`, `predmet:vityaz`.
- Номер не меняется никогда. Новый день ссылается на номер, а не пишет имя заново.
- Поля: `tip` (lyudi / predmet / sobytie), `nazvanie` — как пишем на сайте, `napisaniya` — все
  встреченные написания, `dni` — где встречается, `iz` — откуда взято (slovar.json или текст).
- Перед тем как завести новую карточку — найди человека в файле по фамилии
  (`grep -i фамилия src/data/spravochniki/kartochki.json`). Есть — бери его номер.
- Человек есть под двумя написаниями (Г. В. Титов и Герман Титов) — это одна карточка.
  Машина складывает такие пары в `src/data/spravochniki/kartochki-dubli.json`; разные люди с одной
  фамилией (В. А. Кулик и П. Я. Кулик) там тоже окажутся — это видно по инициалам.

## 170. Единое написание букв

Проверка: `python3 tools/spravochniki/napisanie.py` (подробно — `--json`). К сборке не подключена.

- Только русские буквы в русских словах: латинская «A», «o», «c» внутри слова — ошибка.
- «Ё» пишем везде, где она есть: «лётчики», «самолёты», «озёра». Одно слово то с «ё», то с «е» —
  машина покажет.
- Кавычки — «ёлочки»; внутри ёлочек — „лапки“: «„Ермак“ должен жить». Прямые "…" — ошибка.
- Тире между словами — « — », не дефис.
- Инициалы — через пробел: «А. С. Пушкин».

# Типы и связи дней — закрытый словарь (пункты 34 и 36)

Словарь: `src/data/spravochniki/tipy.json`. Сверка вручную: `python3 tools/spravochniki/tipy.py`.
К сборке не подключена (Р627).

## 34. Тип предмета и события — только из словаря

- В разделе `vidy` словаря `tipy.json` — закрытый список видов: корабль, подводная лодка, ледокол, самолёт, танк, цитата,
  надпись, имя, бой, оборона, плен, изобретение, открытие и другие. Своих слов не пишем.
- У каждого вида: `nazvanie` по-русски, `dlya` (lyudi / predmet / sobytie), `crm` — класс
  CIDOC-CRM (E21 человек, E22 вещь, E33 текст, E34 надпись, E41 имя, E5/E7/E12 событие),
  `aat_termin` — термин словаря Getty AAT по-английски, только для сверки с ним.
- Номера AAT не проставлены: сайт Getty из нашей сети отвечал 403. Номер по памяти не пишем —
  впишем, когда Getty откроется.
- Вид карточки — `src/data/spravochniki/kartochki-vid.json` (номер карточки → код вида).
  Машина `kartochki.py` вписывает его в `kartochki.json` полем `vid`.
- Если под одним номером в разных днях разные вещи, пишем словарь «день → вид».
  Пример: `predmet:vityaz` — корвет 8 января и отряд спецназа 25 января.
- Тип события дня — `src/data/spravochniki/dni-sobytiya.json` (`музей/01-ДД` → код вида
  с `dlya: sobytie`). У дня один главный тип — о чём день.
- Нужного вида нет — добавь строку в `tipy.json` с классом CIDOC-CRM, а не пиши слово в день.

## 36. Связь между днями — с типом

Файл: `src/data/spravochniki/svyazi-dney.json`. Одна связь — одна строка:
`ot`, `k` (дни `музей/01-ДД`), `tip`, `cherez` (номер карточки, если есть), `pochemu`.
Читается так: «день ot — продолжение дня k».

- `prodolzhenie` — продолжение: следующий шаг той же истории (Рязань → Козельск).
- `tot-zhe-geroy` — тот же герой в обоих днях (Костович, Королёв).
- `tot-zhe-predmet` — та же вещь в обоих днях (дирижабль «Россия»).
- `otvet-na` — ответ на: месть, повтор подвига, отклик на событие другого дня.
- `upominaet` — в дне назван герой или предмет другого дня, но сам день о другом.
- Однофамильцы — не связь. Лебедев-физик и Лебедев-конструктор — разные люди.
  Пистолет Макарова и адмирал Макаров тоже не связаны.
- Связь ставим только по тексту дня: строка в фактах, где назван другой день.
